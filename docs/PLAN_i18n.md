## 0. Общие правила (действуют на всех этапах)

1. **Один этап за раз.** После каждого этапа: коммит, отчёт, СТОП и ждать
   подтверждения. Не начинать следующий этап без явного «ОК».
2. **Отдельная ветка `feat/i18n`** от актуального `main` (см. этап A-1).
3. **Перед каждым этапом:** снять базовую линию (baseline) и записать её в отчёт:
   - `cd mobile && npx tsc --noEmit` (количество ошибок)
   - `cd web && npx tsc --noEmit && npm run build`
   - `cd backend && npx tsc --noEmit`
   - `cd mobile && npx expo-doctor`
   После этапа прогнать то же самое. **Новых ошибок быть не должно.**
   Сравнивать с фактом, а не с памятью.
4. **Ничего не удалять «заодно».** Вне рамок этапа ничего не рефакторить.
   Замеченное — записать в отчёт в раздел «Заметил, не трогал».
5. **Миграции БД** — только если этап прямо требует (A4, `User.language`),
   только добавляющие: новая колонка с `DEFAULT`, без `DROP`/`RENAME`.
   Сначала на локальной БД, SQL показать в отчёте.
6. **Секреты** — только в `.env`. Не коммитить `.env`.
7. **Удаление файлов/папок** — не делать самому, попросить меня.
8. Если что-то идёт не по плану (команда упала, гипотеза не подтвердилась) —
   остановиться и показать факты, а не чинить вслепую.

## Принципы
- Стек: **i18next + react-i18next** в web и mobile (один движок).
  Mobile: `expo-localization` (ставить через `npx expo install`).
  Web: `i18next-browser-languagedetector`.
  Backend: `nestjs-i18n` с заголовком `Accept-Language`.
- **Русский не удаляется:** строки переезжают в `ru.json` как есть,
  английский пишется рядом в `en.json`.
- **Общие слова — в `packages/shared`**: значения енумов (UserStatus, SubStatus,
  RequestType, RequestStatus, PaymentStatus, CheckInStatus, CheckOutStatus,
  DayStatus, Weekday, роли) и сообщения zod-схем. Веб и мобилка берут их
  оттуда, чтобы тексты не разошлись.
- Язык по умолчанию — язык системы/браузера, запасной `ru`.
  Выбор пользователя хранить: mobile — `expo-secure-store`, web — `localStorage`.
- Ключи обязаны совпадать в `ru.json` и `en.json`. Сделать скрипт
  `scripts/check-i18n-keys.js`, который сравнивает наборы ключей и падает
  при расхождении. Запускать в конце каждого этапа.
- Английский — деловой, не калька. Глоссарий:
  Приход/Уход = Check in / Check out · Заявки = Requests ·
  Посещаемость = Attendance · Сотрудник = Employee · Расписание = Schedule ·
  Подписка = Subscription · Пробный период = Free trial ·
  Льготный период = Grace period · Приостановлена = Suspended.
- Валюты и цены (₸, $) в этом плане не менять по смыслу: только язык.
  Форматирование чисел и дат зависит от языка, суммы и валюта остаются как есть.

в БД, добавить колонку `User.language` (DEFAULT 'ru') и сохранять при
смене языка в приложении.
